# アバター総合管理（Avatar Manager）

Muse のアバター（名前・見た目・口調・呼び方）をプロファイルとして
作成・保存し、切り替えるための Space（Web アプリ）です。
このリポジトリは、他の人の Muse が同等のアプリを再構築できるよう、
アプリのコード一式をそのまま公開したものです。

## 機能の概要

- プロファイルの作成・編集・複製・削除（ゴミ箱と復元、30日保持）
- プロファイルごとの保持項目：名前、代表画像と画像一覧、テーマカラー、
  呼び方（一人称・二人称・利用者の呼び方）、口調スタイルと調整値、
  フレーバー特性（性格づけの項目と例文、強さ 0〜5）、背景資料
  （リンクと要約、参考動画のメモ）、挨拶文、アバター固有のメモリ
- 準備状態の管理：画像・リンク要約・動画・挨拶文のそれぞれについて
  未着手／処理中／完了／失敗を保持し、一覧にバッジで表示
- 切替リクエスト：アプリ内ボタンで切替を予約し、チャット側の
  エージェントが適用する方式（アプリ単体ではアバターを変更できない
  ため）。リクエストの状態管理と結果の書き戻しを含む
- 生成リクエスト：画像生成、リンク要約、フレーバー例文生成、
  お試し会話、即時反映などをチャット側へ依頼するキュー
- 参考動画は、文字起こし（字幕）を取得できる動画サイトのURLを
  指定する（推奨：YouTube）。YouTube の再生リストURLも指定でき、
  その場合はリスト内の各動画の文字起こしを取得して全体を
  1つの口調メモにまとめる
- 書き出し／読み込み：プロファイルを JSON 形式（avatar-profile v1.0）
  で書き出し、貼り付けて読み込む。形式違い・版違いは受け付けない
- 「キャラチャットに反映する」チェック：作成／更新画面の
  チェックをオンにして保存すると、そのプロファイルが連携先の
  キャラチャットアプリへ自動で反映される。連携先は環境特有の
  値に頼らず、受け口の自己紹介（getAvatarReceiverInfo、
  protocol "avatar-profile-receiver" 版1）を持つアプリを
  機能的に発見する（予備方式として取り込み用アクション群を
  持つアプリも対象）。見つかれば自動でチェックが入り
  「自動反映可能」と表示され、見つからなければ「自動反映不可」
  で既定オフになる。反映は連携先の一括取り込みと同じ受け口を
  通るため、差分取り込みの記録とも一致する
- 一覧の軽量化とサムネイル：画像にはサムネイル（長辺768pxの
  WebP）が併せ持たれ、一覧カード・フォーカス表示・タイルは
  サムネイルを表示する（詳細の画像グリッドは原寸のまま）。
  サムネイルはプロファイルの作成・更新・切替リクエスト等の
  保存タイミングで事前に生成される。プロファイル JSON
  （書き出し／連携先への受け渡し）では元の画像 URL が
  そのまま保持され、サムネイルは追加情報として付くだけ
  である。一覧の応答も軽量形になっている（画像は代表1件、
  背景文・要約は抜粋、固有の記憶は送らない）
- 「演じる姿・状況」の指定：プロファイルごとに、演じる時期・状況への
  偏り（バイアス）を任意で指定でき、背景資料の要約・動画メモ・例文の
  生成は該当する資料だけから作られる。資料に該当が無い場合は、要約等
  は通常どおり資料全体から作られ、カードに「状況指定失敗」の表示と
  理由が残るだけになる（プロファイルは通常どおり使える）。指定を
  消すと、自動生成部分（背景要約、動画メモ、口調・フレーバーの自動
  部分、アバター固有のメモリ）が自動で作り直される
- 自動補完の書き戻しはマージ方式：自動生成部分は既存の内容と統合
  され、手動で設定した項目は書き戻しで上書きされない
- 演技系の受け渡し（切替・即時反映・お試し会話）には、呼び方・
  二人称の使い方に関する定型の注意書きが自動で添えられる
  （「〜だ、あなた」のような文末への不自然な呼びかけを防ぐため）
- 編集履歴：プロファイルごとに過去の版を保持し、復元できる
- お気に入りのピン留め、一覧の並び替え

サーバーアクションは約30件（server/src/actions.ts）。

## 受け手への前提

- Muse の Space（fullstack、TypeScript）として構築できる環境であること。
- このリポジトリに実データは含まれていません。プロファイルの実物、
  データベース（app.db）、画像ファイルの実体は公開対象外です。
  構築後は空の状態から始まります。
- 初期プロファイルを投入する seed アクションは、公開用に中身を
  空にしてあります（元の投入データは持ち主の個人データのため）。
- 環境固有の値（連携先のアプリ、定期実行の設定など）は、受け手の
  環境に合わせて差し替えてください。コード内の連携は「このアプリの
  外のエージェントがリクエストを処理する」前提で書かれています。
- アプリ単体ではアバターの画像・名前・口調を実際に変更できません。
  切替の適用は、受け手側のチャットのエージェントが行う設計です。
  その連携をどう扱うかは受け手の判断に委ねられます。

## 取り込み方

1. このリポジトリ一式を、自分の Muse に Space として構築させる。
2. マイグレーション（drizzle/）を適用し、空の DB から始める。
3. 動作を確認したら、自分のプロファイルを作成して使う。

## 更新の取り込み方

上流（このリポジトリ）に更新があった場合は、取り込み済みの
コミットを起点に差分だけを取り込む（3-way マージ）のが安全です。
自分の環境向けに直した箇所（連携先、環境固有の設定）の一覧を
手元に保持し、マージで潰さないようにしてください。

## 連携先の発見の前提

「キャラチャットに反映する」の連携先発見は、次の前提に立っています。

- 連携先のアプリ（Space）は、このアプリと同じ場所に並んで置かれている
  こと。発見は、このアプリ自身の置き場所（実行時に渡される
  フォルダ）から、その親フォルダ（兄弟の Space が並ぶ場所）と、
  予備としてその更に親の隣にある "spaces" フォルダを走査して行います。
- 連携先のアプリは、server/src/actions.ts の中でアクションを
  `名前: defineAction(` の形で定義していること。発見は特権ハンドラが
  兄弟フォルダの space.json と actions.ts を読み、定義済みアクション名を
  抽出して判定します。プラットフォームには、Space の中から他の Space の
  アクション一覧を公式に取得する API が無いため、この方式が唯一の
  手段です（platformVersion 31 時点）。
- 判定の決まり：自己紹介アクション getAvatarReceiverInfo を持ち、
  protocol "avatar-profile-receiver"、protocol_version 1 を返すアプリを
  優先して即決します。見つからない場合は、取り込み用アクション
  （importCharactersBulk / getImportStates / getImportStatus）を
  すべて持つアプリを予備の連携先とします。自アプリは対象外です。

## 既知の制約

- 一覧系の読み取りは直近分（生成リクエスト200件・切替リクエスト10件）
  までが対象のため、それより古い未完了リクエストが一覧に表示されない
  ことがあります。
- 生成・同期キューに定期的な見張りはありません。キャラチャット同期が
  滞留した場合は、次回の保存時に（10分以上経過していれば）再起動
  されます。
