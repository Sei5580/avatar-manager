# アバター総合管理（Avatar Manager）

Muse のアバター（名前・見た目・口調・呼び方）をプロファイルとして
作成・保存し、切り替えるための Space（Web アプリ）です。
このリポジトリは、他の人の Muse が同等のアプリを再構築できるよう、
アプリのコード一式をそのまま公開したものです。

## 機能の概要

- プロファイルの作成・編集・複製・削除（ゴミ箱と復元、30日保持）
- プロファイルごとの保持項目：名前、代表画像と画像一覧、テーマカラー、
  呼び方（一人称・二人称・利用者の呼び方）、口調スタイルと調整値、
  フレーバー特性（性格づけの項目と例文、強さ 0〜5）、背景資料
  （リンクと要約、参考動画のメモ）、挨拶文、アバター固有のメモリ
- 準備状態の管理：画像・リンク要約・動画・挨拶文のそれぞれについて
  未着手／処理中／完了／失敗を保持し、一覧にバッジで表示
- 切替リクエスト：アプリ内ボタンで切替を予約し、チャット側の
  エージェントが適用する方式（アプリ単体ではアバターを変更できない
  ため）。リクエストの状態管理と結果の書き戻しを含む
- 生成リクエスト：画像生成、リンク要約、フレーバー例文生成、
  お試し会話、即時反映などをチャット側へ依頼するキュー
- 書き出し／読み込み：プロファイルを JSON 形式（avatar-profile v1.0）
  で書き出し、貼り付けて読み込む。形式違い・版違いは受け付けない
- 編集履歴：プロファイルごとに過去の版を保持し、復元できる
- お気に入りのピン留め、一覧の並び替え

サーバーアクションは約30件（server/src/actions.ts）。

## 受け手への前提

- Muse の Space（fullstack、TypeScript）として構築できる環境であること。
- このリポジトリに実データは含まれていません。プロファイルの実物、
  データベース（app.db）、画像ファイルの実体は公開対象外です。
  構築後は空の状態から始まります。
- 初期プロファイルを投入する seed アクションは、公開用に中身を
  空にしてあります（元の投入データは持ち主の個人データのため）。
- 環境固有の値（連携先のアプリ、定期実行の設定など）は、受け手の
  環境に合わせて差し替えてください。コード内の連携は「このアプリの
  外のエージェントがリクエストを処理する」前提で書かれています。
- アプリ単体ではアバターの画像・名前・口調を実際に変更できません。
  切替の適用は、受け手側のチャットのエージェントが行う設計です。
  その連携をどう扱うかは受け手の判断に委ねられます。

## 取り込み方

1. このリポジトリ一式を、自分の Muse に Space として構築させる。
2. マイグレーション（drizzle/）を適用し、空の DB から始める。
3. 動作を確認したら、自分のプロファイルを作成して使う。

## 更新の取り込み方

上流（このリポジトリ）に更新があった場合は、取り込み済みの
コミットを起点に差分だけを取り込む（3-way マージ）のが安全です。
自分の環境向けに直した箇所（連携先、環境固有の設定）の一覧を
手元に保持し、マージで潰さないようにしてください。
